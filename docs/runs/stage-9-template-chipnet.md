# Stage 9 run on chipnet (run E, steps 2 and 3): a ParyonUSD loan through the wallet from the Paryon template, and through the loss of the device

Written by the run itself (`scripts/run-e-template.ts chipnet`). The owner's wallet, the recoverer and the new device, each on the XO engine, on chipnet, against Paryon's deployment `chipnet-fast-periods-6`. Each part ran in a process of its own with an empty engine state. The Paryon template and its recovery declaration reached the wallet as texts, as the loan's page sends them (`packages/paryon`'s requests), and were stored in the backup before the first signature. Every transaction of the loan is an invitation of that template, built by the unmodified engine, which signed the wallet's own inputs, and compared, output by output and input by input, with what the wallet's own code had worked out. A coin of Paryon's is at a script every user of Paryon shares; where the template marks such a script as one a wallet need not track, the wallet gave the coin to the engine with the unlocking it worked out from the template (arguments and redeem script, no signature), and the engine put it into the transaction as given; each step says which coins of Paryon's the engine unlocked by the template itself and which it was given. Every input of every transaction was evaluated in the virtual machine before it was signed and again before it was sent, and each was tried with `testmempoolaccept` on the owner's chipnet node before it was sent. The wallet's code names no application: what it did for the loan came from the template, its declaration and the chain.
